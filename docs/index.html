Desafio técnico · outubro de 2024

VPC, EC2 e Nginx na AWS, descritos num único main.tf.

Infraestrutura como código para um processo seletivo (VExpenses): rede isolada, sub-rede pública, security group restritivo e uma instância Debian 12 que já sobe servindo Nginx. Aqui está o código real, o desenho do que ele cria e uma revisão honesta, feita em 2026, do que eu mudaria antes de levar para produção.

01 · O desafio

Pegar um main.tf base, entender, endurecer e automatizar.

O que foi pedido

  1. Análise técnica. Descrever cada recurso do arquivo fornecido: provider, chaves, rede, security group, EC2 e outputs.
  2. Melhorias de segurança. Fechar o que estava aberto demais no código base.
  3. Nginx automático. A instância precisa instalar e iniciar o Nginx sozinha, já na criação.
  4. Documentação. Explicar as mudanças e como rodar.

Reconstruído a partir do README da entrega; o enunciado original não está no repositório.

O que eu entreguei

  • ingress

    SSH só de uma faixa de IP (203.0.113.0/24), em vez de qualquer origem.

    linha 89
  • egress

    Saída limitada a 80 e 443: o suficiente para o apt e downloads.

    linha 94
  • user_data

    Nginx no boot: atualiza pacotes, instala, inicia e habilita o serviço.

    linha 147
  • s3 + iam

    Extras: bucket de backup com versionamento e um usuário IAM com política própria.

    linha 162

04 · Como rodar

Do init ao destroy, sem nenhuma credencial no código

Pré-requisitos

  • Terraform CLI 1.x e AWS CLI v2 instalados.
  • Uma conta AWS de estudo (nunca a conta de produção, nunca o usuário root) com permissão para VPC, EC2, S3 e IAM.
  • Os ajustes da revisão aplicados: do jeito que está, o arquivo não passa do validate.

Credenciais

O provider aws lê as credenciais do ambiente; o main.tf não tem nenhuma, e deve continuar assim.

  • Login temporário com aws configure sso e aws sso login --profile desafio, depois AWS_PROFILE=desafio no terminal.
  • No CI, papel assumido via OIDC (GitHub Actions), sem chave fixa guardada em lugar nenhum.
  • Nunca: chave no bloco provider, em .tfvars versionado ou no README. O .gitignore do repositório já barra .terraform/ e *.tfstate*.
terminalbash
# 1. baixa os providers (aws e tls)
terraform init
# 2. formatação e sintaxe
terraform fmt -check
terraform validate
# 3. revisa o que vai ser criado
terraform plan -out plano.tfplan
# 4. cria exatamente o que está no plano
terraform apply plano.tfplan
# 5. IP público da instância
terraform output ec2_public_ip
# 6. chave SSH: fica só na sua máquina
terraform output -raw private_key > chave.pem
chmod 400 chave.pem
ssh -i chave.pem admin@<ip-publico>
# 7. ao terminar, derruba tudo
terraform destroy

05 · Segurança

O que está aberto, o que está largo e o que eu endureceria

Portas no security group

DireçãoPortaOrigem / destinoPara quê
Entrada22/tcp203.0.113.0/24SSH
Saída80/tcp0.0.0.0/0apt via HTTP
Saída443/tcp0.0.0.0/0HTTPS
Entrada80/tcpnenhuma regrao Nginx roda, mas não é alcançável de fora

Security groups são stateful: a resposta do SSH volta sem regra de saída. O DNS da VPC não passa pelo security group, então o apt resolve nomes mesmo sem a porta 53 liberada.

Menor privilégio

A TerraformPolicy libera ec2:* e s3:* em Resource: *. Funciona, mas é bem mais do que "permissões limitadas", como dizia o README.

  • Ações específicas (ec2:RunInstances, ec2:Describe*...) e recursos por ARN ou por tag com aws:ResourceTag.
  • Papel com credencial temporária no lugar de usuário IAM com chave de acesso fixa.
  • No bucket, bloqueio de acesso público e criptografia declarados no código, mesmo já sendo padrão da AWS para buckets novos.
ver a política, L183

Endurecimento para produção

  1. SSH. Trocar a faixa por um IP /32, ou melhor, fechar a porta 22 e entrar pelo SSM Session Manager com um instance profile (AmazonSSMManagedInstanceCore). L89
  2. IMDSv2 obrigatório. metadata_options { http_tokens = "required" } na instância, contra roubo de credencial via SSRF. L132
  3. Estado remoto. Backend S3 com criptografia, versionamento e lock (use_lockfile). Hoje o state local guarda a chave privada em texto puro. L18
  4. Tags padrão. default_tags no provider (projeto, dono, ambiente, centro de custo) no lugar de repetir Name em cada bloco. L2
  5. Versões fixas. Bloco required_providers com versão do aws e do tls, e o .terraform.lock.hcl versionado.
  6. Disco. gp3 com encrypted = true: mais barato que gp2 e cifrado em repouso. L141
  7. Web. Publicar o Nginx atrás de um load balancer ou CloudFront com HTTPS, em vez de abrir a porta 80 na instância.

Revisão de 2026

O que impede o apply hoje

Leitura do código, sem aplicar na AWS. Mantive o arquivo como foi entregue; os ajustes ficam documentados aqui.

  1. aws_route_table_association não aceita tags: o terraform validate para no argumento não suportado. L73
  2. security_groups recebe nomes e só vale na VPC padrão. Numa VPC própria o certo é vpc_security_group_ids = [aws_security_group.main_sg.id]. L137
  3. O nome do bucket vira VExpenses-SeuNome-backup, e o S3 só aceita minúsculas (o nome também precisa ser único no mundo). O bloco versioning embutido está obsoleto desde o provider 4: o recurso atual é aws_s3_bucket_versioning. L163
  4. 203.0.113.0/24 é uma faixa reservada para documentação (RFC 5737). Serve de exemplo, mas nenhum cliente real conecta a partir dela: troque pelo seu IP. L89
  5. Sem regra de entrada na porta 80, a página padrão do Nginx só aparece por dentro (ou por um túnel SSH).

06 · Custo

Cabe no free tier, se você lembrar do destroy

  • EC2

    t2.micro

    No free tier clássico (contas criadas antes de 15/07/2025): 750 horas por mês durante 12 meses. Contas novas usam o plano gratuito com créditos; confira no console quais tipos entram.

  • EBS

    20 GB gp2

    Dentro dos 30 GB de EBS do free tier clássico. Fora dele, cobrado por GB por mês enquanto o volume existir.

  • IPv4

    IP público

    A AWS cobra por hora cada IPv4 público desde fevereiro de 2024; o free tier clássico cobre 750 horas por mês no primeiro ano.

  • S3

    Bucket versionado

    Centavos para um backup pequeno, mas toda versão antiga também ocupa espaço e é cobrada.

Terminou de testar? terraform destroy. Ele remove tudo o que o apply criou. Um bucket com objetos falha no destroy (BucketNotEmpty): esvazie antes ou use force_destroy num ambiente de estudo.

Preços e regras do free tier mudam. Confira a página de preços da AWS antes de aplicar.
